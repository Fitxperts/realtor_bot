# РиелторБот

Telegram-бот для риелтора с тремя ролями (клиент, собственник, администратор).
Стек: Python 3.11, aiogram 3.x, PostgreSQL + SQLAlchemy (async), Redis (FSM),
Anthropic API, APScheduler, Docker.

## Быстрый старт (Docker)

```bash
cp .env.example .env      # заполните BOT_TOKEN, ADMIN_TELEGRAM_ID, CHANNEL_ID, ANTHROPIC_API_KEY
docker compose up --build
```

Контейнер бота при старте применяет миграции (`alembic upgrade head`) и
запускает бота.

## Переменные окружения (.env)

| Переменная | Назначение |
|---|---|
| `BOT_TOKEN` | токен Telegram-бота |
| `ADMIN_TELEGRAM_ID` | ID администратора(ов) через запятую |
| `CHANNEL_ID` | канал публикации (`@username` или числовой id) |
| `DATABASE_URL` | `postgresql+asyncpg://user:pass@db:5432/realtor` |
| `REDIS_URL` | `redis://redis:6379/0` |
| `ANTHROPIC_API_KEY` | ключ Anthropic |

## Режим webhook (опционально)

По умолчанию бот работает через **polling**. Чтобы убрать паузы приёма при
нестабильной сети, можно включить **webhook** (Telegram сам присылает апдейты):

1. Домен → A-запись на IP сервера; порты 80 и 443 открыты.
2. В `.env`: `DOMAIN=bot.example.com`, `WEBHOOK_URL=https://bot.example.com`,
   `WEBHOOK_SECRET=<случайная строка>`, `WEBHOOK_PORT=8080`.
3. Запуск:
   - **Свободные 80/443** → Caddy (авто-TLS): `docker compose -f docker-compose.yml -f docker-compose.webhook.yml up --build -d`
   - **Уже есть Nginx Proxy Manager / другой прокси на 80/443** → без Caddy,
     через NPM: задать `NPM_NETWORK` в `.env`, запустить
     `docker compose -f docker-compose.yml -f docker-compose.npm.yml up --build -d`,
     и добавить в NPM Proxy Host: домен → `Forward Hostname: realtor-bot`, порт `8080`.

Если `WEBHOOK_URL` пуст — бот остаётся на polling, ничего не меняется.

## Авто-репост из чужих каналов (юзербот)

Отдельный процесс на Telethon мониторит каналы партнёров/конкурентов, разбирает
объявления ИИ, переделывает под шаблон агентства (с водяным знаком) и отдаёт
в модерацию или сразу в канал. Бот сам читать чужие каналы не может — нужен
аккаунт-«читатель».

1. Получи `API_ID`/`API_HASH` на https://my.telegram.org.
2. Один раз сгенерируй сессию: `python scripts/userbot_login.py` → строка в `USERBOT_SESSION`.
3. В `.env`: `USERBOT_ENABLED=true`, `TELEGRAM_API_ID`, `TELEGRAM_API_HASH`,
   `USERBOT_SESSION`, `SOURCE_CHANNELS=@a,@b`, `AUTOREPOST_MODE=moderate|auto`.
4. Запуск (добавь override): `... -f docker-compose.userbot.yml up -d --build`.

⚠️ Юзерботы формально против ToS Telegram — используй ОТДЕЛЬНЫЙ номер. Репост
чужого контента — на твоё усмотрение и ответственность.

## Миграции (Alembic)

Схемой БД управляет Alembic (не `create_all`).

```bash
alembic upgrade head                              # применить миграции
alembic revision --autogenerate -m "add field"   # создать новую миграцию после правки моделей
alembic downgrade -1                              # откатить последнюю
```

`migrations/versions/0001_initial.py` — базовая схема (properties, clients,
meetings, bot_users).

## Языки

Весь интерфейс — на трёх языках: **узбекский, русский, английский** — для
клиента, собственника **и администратора**. Язык выбирается при первом входе
и меняется кнопкой «🌐 Til / Язык / Language» (у админа — в его меню). Выбор
хранится в `bot_users.language`. Публичное объявление в канал — на узбекском
(единый шаблон). Уведомления, которые бот рассылает нескольким админам сразу
(модерация нового объекта), остаются на русском как единый канонический текст.

Быстрый ввод объявления одним сообщением понимает **русский и узбекскую
латиницу**: `2x margʻilon 450000 sotuv egasi +998...` распознаётся так же, как
`2к маргилан 450000 продажа хозяин +998...`.

## Поддержка

В `/help` есть кнопка «✍️ Задать вопрос / Ошибка»: сообщение уходит всем
администраторам с контактом пользователя. Админ отвечает командой
`/reply <telegram_id> текст` — ответ доставляется пользователю на его языке.

## Роли и сценарии

- **Клиент** — анкета подбора недвижимости в Фергане, показ подходящих
  объектов, выбор времени звонка.
- **Собственник** — размещение объекта **одним сообщением**: пользователь
  присылает объявление целиком (своё или готовое от партнёра), в т.ч. фото и
  видео альбомом — бот забирает все медиа из присланного. ИИ разбирает поля и
  оформляет описание в стиле агентства; адрес-ориентир («за рестораном»,
  «рядом с домом») сохраняется как есть. Вручную бот дозапрашивает только
  недостающее критичное: тип сделки, цену, район/массив (выбор из списка
  ферганских массивов), телефон. Затем модерация; раздел «Мои объекты».
- **Администратор** — модерация с публикацией в канал, редактирование,
  CRM-воронка клиентов, встречи, публикации, статистика.

## Каталог и фильтры

«📋 Объявления» — лента активных объектов с фото и кнопкой «Оставить заявку».
«🔎 Фильтр»: сделка, район (показываются только районы, где есть объявления, с
числом), комнаты (1/2/3/4+), цена «до» — своя шкала для аренды ($200–700) и
продажи ($20k–100k), цены в сумах пересчитываются в доллары. Район узнаётся в
любом написании (Qirg'uli = Киргули). Фильтр хранится в кнопках — не мешает
анкетам и работает после перезапуска.

## Подписки на поиск

Заявка клиента («Подобрать жильё») — это и подписка: когда публикуется
подходящий объект, бот присылает его клиенту на его языке с кнопками
«Оставить заявку» и «Отписаться». Кнопка «🔔 Мои подписки» — список и отписка.
После заявки по конкретному объекту бот предлагает «Присылать похожие» —
без согласия не подписывает.

- Бюджет понимается как пишут люди: «400$», «до 400 у.е.», «4 млн», «3,5 mln so'm»,
  «45.000». Без валюты и меньше 10 000 — доллары.
- Цены в $ и сумах сравниваются в долларах по курсу `USD_RATE` (по умолчанию 12 000).
- Антиспам: один объект человеку — один раз, не больше `ALERTS_DAILY_LIMIT` (5)
  уведомлений в сутки, владельцу его же объект не шлём.

## Проверка актуальности

Проданное и сданное уходит из каталога само. Через 14 дней после публикации
(или последнего подтверждения) бот спрашивает владельца «Объявление ещё
актуально?» — «✅ Да» / «⛔ Сдано/продано». У объектов из авто-репоста владельца
нет — спрашивают админов. Нет ответа 3 дня — объект в архив, пост в канале
помечается «Эълон долзарб эмас», владельцу приходит кнопка «вернуть». Пока ждём
ответа, объект не поднимается. Не больше 5 вопросов одному человеку за день.
В демо-боте выключено.

## Аналитика агентства

Админ → «📊 Статистика»: кроме счётчиков объектов и воронки клиентов — блок
«📈 Активность за 7 дней» (в скобках — изменение к прошлым 7 дням): новые
пользователи, просмотры объектов в каталоге, нажатия «Оставить заявку» (из
канала и каталога), заявки с телефоном, анкеты на подбор, объявления через бота
и из авторепоста, публикации, уведомления по подпискам; конверсия «клик → заявка»
и «просмотр → клик»; топ-5 объектов за 30 дней. Каждый понедельник в 09:00 тот же
отчёт за неделю приходит админам сам.

Telegram не отдаёт ботам просмотры постов канала — считается то, что проходит
через бота (таблица `events`; сбой записи события никогда не ломает сценарий).

## Контроль качества разбора

50 объявлений в стиле ферганских каналов (`bot/evals/listings.json`: русский,
узбекская латиница и кириллица, сленг, опечатки, «лям», «ming», «у.е.», ориентиры)
с ожидаемыми полями + 15 контрольных (`holdout.json`). Прогон показывает точность
по каждому полю (сделка, вид, комнаты, этаж, площадь, цена, валюта, район,
телефон, ориентир) и где именно модель ошиблась.

```bash
docker compose exec bot python -m bot.evals.run            # через цепочку ИИ, как в боте
docker compose exec bot python -m bot.evals.run --offline  # запасной разбор без ИИ
```

В боте: `/ai_eval` (или `/ai_eval 10` — первые 10, `/ai_eval offline`). Запускайте
после смены модели или ключа. Запасной разбор без ИИ переписан: 65% → 100% на
наборе и 98% на контрольных при первом прогоне; тест не даёт ему деградировать.
Добавляйте в набор реальные объявления — тем честнее проверка.

## Фоновые задачи (APScheduler, TZ Asia/Tashkent)

- автоподнятие активных объектов (ежедневно 10:00, объекты старше 3 дней);
- напоминания о встречах за день / за 2 часа / за 30 минут;
- проверка актуальности объявлений (ежедневно 11:00) — см. выше;
- отчёт агентства за неделю (понедельник 09:00) — см. выше;
- копия ночного бэкапа базы в Telegram (04:10) — см. ниже;
- сторож ИИ (каждые 5 минут): если все ИИ-провайдеры не отвечают дольше
  10 минут — админам приходит тревога с ошибкой каждого провайдера и
  подсказкой (модель сняли / ключ / лимит), когда ИИ ожил — «снова работает».
  Без запросов 30 минут сторож сам делает короткую проверку, так что о
  снятой модели вы узнаете раньше клиентов. Тревога — не чаще раза в час.

## Демо-бот для продаж

Отдельный бот на том же коде (`DEMO_MODE=true`) — ссылку даёшь агентству на
встрече, и человек сам пробует бот со своего телефона:

- 18 примеров объявлений по Фергане (аренда/продажа, квартиры, дома, участки,
  коммерция) уже лежат в каталоге и в демо-канале;
- посетитель оставляет заявку → видит, как она приходит агентству;
- посетитель размещает объявление одним сообщением → оно сразу выходит в
  демо-канал, плюс показ «как это видит администратор» (до 3 в день);
- кнопка «💼 Хочу такой бот» → его телефон приходит тебе как лид;
- каждую ночь в 05:00 всё, что накликали посетители, удаляется (их посты в
  канале тоже), примеры восстанавливаются.

Запуск (своя база `realtor_demo` создаётся сама, вебхук не нужен):

```bash
cp .env.demo.example .env.demo        # токен демо-бота, публичный демо-канал, контакты
# в .env: COMPOSE_FILE=…:docker-compose.demo.yml
docker compose up -d --build demo
docker compose logs -f demo           # «Демо-режим: примеров создано 18, опубликовано 18»
```

Реальные фото вместо нарисованных обложек: положите их в папку `demo_photos/`
с именами `apartment_*.jpg`, `house_*.jpg`, `land_*.jpg`, `commercial_*.jpg`.

## Бэкапы базы

Сервис `backup` (в `docker-compose.yml`) каждую ночь после 03:00 делает дамп
Postgres в папку `backups/` на сервере, проверяет его (`pg_restore --list`) и
хранит 14 дней. В 04:10 бот присылает свежий файл в Telegram — `BACKUP_CHAT_ID`
(id чата/канала) или первому админу. Если бэкап упал или свежего нет больше
26 часов — админам приходит предупреждение.

```bash
docker compose exec backup sh /backup.sh --once         # бэкап прямо сейчас
docker compose logs backup                              # журнал бэкапов
sh scripts/restore_backup.sh backups/realtor-2026-10-17_0300.dump   # восстановление
```

Админ-команда `/backup` — прислать последний бэкап в чат прямо сейчас.
Восстановление останавливает бота, заменяет данные из файла (спросит `yes`)
и запускает бота обратно. Файл из Telegram сначала положите в `backups/`.
Дамп больше 45 МБ Telegram не примет — бот предупредит, тогда нужно внешнее
хранилище (S3/Backblaze).

## Экспорт и наблюдаемость

- Админ → «📊 Статистика» → кнопки экспорта объектов/клиентов в **Excel (.xlsx)**
  или **CSV** (CSV с BOM — корректно открывается в Excel с кириллицей).
- Логи: `LOG_FORMAT=json` включает структурный JSON-вывод (для ELK/Loki),
  `LOG_LEVEL` управляет уровнем.
- **Sentry / GlitchTip** (GlitchTip — бесплатный self-hosted аналог Sentry):
  задайте `SENTRY_DSN` из настроек проекта — ошибки бота и юзербота (в т.ч. из
  глобального error-handler) уедут туда автоматически, с тегом `service`.

## Оформление объявлений (премиум-эмодзи)

стоят заглушки — используются обычные эмодзи.
